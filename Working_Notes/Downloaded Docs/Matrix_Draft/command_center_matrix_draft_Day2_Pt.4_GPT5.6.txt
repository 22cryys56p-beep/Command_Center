## Step 4BV — Category 65: Project State vs. Project Visibility

This distinction is worth locking down because otherwise CC will eventually start making strange assumptions about what "inactive" means.

A Project can be **inactive without being hidden**.

And something can be **visible without being active**.

Those are different dimensions.

### 1. Project State answers: "What is happening with it?"

For example:

```text
IDEA
PLANNING
ACTIVE
PAUSED
WAITING
BLOCKED
COMPLETED
CANCELLED
```

These describe the **condition of the Project**.

### 2. Visibility answers: "Where should I encounter it?"

That's different.

A Project might be:

```text
State: PAUSED
Visibility: Ongoing
```

because you still want it readily accessible.

Another might be:

```text
State: COMPLETED
Visibility: Archive
```

And an Idea might be:

```text
State: IDEA
Visibility: Ideas
```

### 3. Don't overload State with location

We shouldn't create something like:

> `ARCHIVED`

and use that to mean both:

* the Project is completed; and
* the Project should appear in Archive.

Those are separate facts.

Instead:

```text
State:
COMPLETED

Visibility:
ARCHIVE
```

This becomes especially useful if you later want to revisit a completed Project.

### 4. "Waiting" deserves its own state

This is a common real-world condition:

> "Nothing is wrong. I'm simply waiting for someone/something."

For example:

```text
Teacher Toolbox
State: WAITING

Waiting For:
Claude review
```

That is different from:

> **BLOCKED**

where something prevents progress and requires intervention.

### 5. Paused is also different

Paused means:

> **Kurt intentionally stopped active work.**

Blocked means:

> **Work cannot proceed because of an obstacle.**

Waiting means:

> **The next meaningful event depends on something external.**

Those distinctions can eventually make Attention much smarter.

### 6. Completed doesn't necessarily mean forgotten

A completed Project can still be:

* searched;
* reopened;
* used as a Source;
* mined for Seeds;
* referenced by another Project;
* examined for historical Decisions.

So:

```text
COMPLETED
```

doesn't mean:

```text
DELETED
```

or even:

```text
INVISIBLE
```

### 7. Visibility can probably be multi-valued

This gets interesting.

A Project could legitimately be:

```text
Primary location:
Archive

Also visible in:
Search
Knowledge Base
Related Projects
```

So "visibility" may eventually be less like a single folder and more like a set of **surfaces on which the Project is discoverable**.

We don't need to implement that complexity now.

But the underlying model shouldn't prevent it.

### 8. Ideas are deliberately different

An Idea doesn't necessarily need to become a Project.

This preserves the **spitballing space** we discussed earlier.

```text
IDEAS
│
├── Random thought
├── Possible future project
├── New Project canvas
└── Half-formed concept
```

Eventually:

```text
Idea
  ↓
Promote
  ↓
Project
```

But there should be no requirement that every Idea becomes one.

### 9. A Project can move without changing identity

This is another reason for stable IDs.

```text
CC-042

Ideas
   ↓
Planning
   ↓
Ongoing
   ↓
Paused
   ↓
Ongoing
   ↓
Completed
   ↓
Archive
```

It's still:

> **CC-042**

throughout its entire life.

### 10. State transitions should be recorded

This gives us a useful History chain:

```text
IDEA
  ↓
PLANNING
  ↓
ACTIVE
  ↓
WAITING
  ↓
ACTIVE
  ↓
COMPLETED
```

CC can therefore eventually answer:

> "How did this Project get here?"

without relying on someone's memory.

### Category 65 verdict

The model becomes much cleaner:

```text
              PROJECT
                 │
       ┌─────────┴─────────┐
       │                   │
     STATE              VISIBILITY
       │                   │
   "What's happening?"   "Where do I see it?"
```

So a Project can be:

> **WAITING + Ongoing**

or:

> **COMPLETED + Archive**

or even:

> **PAUSED + Ongoing**

without forcing the system into contradictory categories.

And that gives us a very natural lifecycle:

**Idea → Planning → Active → Waiting/Paused/Blocked → Active → Completed → Archive**

while the Project's identity remains constant throughout.
